# 002: Written conclusions in the report

**Status**: Implemented
**Created**: 2026-10-07

## Problem

The report gives tables and intervals but no reading of them.
A reader has to work out for themselves which variant wins, what the gaps mean, and how far to trust them.
The report notes the 200-message sample and when a gap is within noise, but it never says the dataset is synthetic or that a Claude model wrote it, which matters because three of the six variants are Claude.
Conclusions written once in a chat session are lost, and conclusions pasted into a generated report vanish the next time it is rebuilt.

## Scope

**In**:
- Written conclusions for a specific run, kept in the repository and shown in that run's report.
- A check that every figure the conclusions quote is a figure that run's public report shows, quoted the way the report shows it.
- A statement in every report of how its dataset was made, independent of whether anyone writes conclusions.

**Out**:
- Conclusions written by a model at report time. They are written by a person, or drafted and then approved by one, so that what the report says is something the owner stands behind.
- Charts or other new visuals. That is a separate change.
- Rewriting spec 001's report contents. Everything 001 requires stays as it is; this spec only adds to it.

## Behavior

**B1. Tied to one run.** Conclusions are written for a specific run and kept in the repository.
They appear only in that run's report, never in a report built from another run, so a rebuild from a newer run cannot carry old conclusions forward unnoticed.

**B2. Shown in both editions.** Both editions show the conclusions near the top, under a heading that marks them as written analysis rather than generated output, with the run they were written for.
A run with no conclusions has no conclusions section at all, not an empty one.

**B3. Figures must match the report.** Every figure the conclusions quote (a percentage, a dollar amount, a duration, or a point difference) must appear, exactly as printed, in that run's public edition as it reads without the conclusions section.
"Exactly as printed" includes the unit and its absence: the report prints an interval as `92.3 to 98.0`, so `92.3%` does not match it, and a figure the report never prints, such as a run's total cost, cannot be quoted at all.
A figure the report marks as a lower bound must be quoted with that marker (`≥` or "at least"), so the conclusions can never state a lower bound as the cost (constitution Principle 2).
If any figure fails, neither edition is written, and the failure names each one.
Checking against the public edition, not the full one, means the conclusions can never publish a figure the public edition leaves out (constitution Principle 6).

**B4. Rendered as text.** The conclusions support paragraphs, lists, and emphasis, and nothing else.
Anything that looks like HTML or a script is shown as text, not run.

**B5. How the data was made.** Every report, with or without conclusions, states that its dataset is synthetic and names the model that generated it, taken from the frozen dataset's own record rather than written by hand.
When that generator comes from the same vendor as any variant under test, the report says so next to the statement.

## Acceptance

- **B1.** Given conclusions written for run A, when the report for run B is built, then run B's report has no conclusions section.
- **B2.** Given conclusions for a run, when both editions are built, then each shows them under the written-analysis heading, naming the run.
- **B2.** Given a run with no conclusions, when its report is built, then the report has no conclusions heading.
- **B3.** Given conclusions quoting "94.0%" for a variant whose public report shows 94.0%, when the report is built, then it succeeds.
- **B3.** Given conclusions quoting "93.0%" where no such figure appears in the public edition, when the report is built, then no edition is written and the error names "93.0%".
- **B3.** Given a figure that appears only in the full edition, when the report is built, then it fails as unmatched.
- **B3.** Given conclusions quoting a figure that appears nowhere else in the report, when the report is built, then it fails even though the figure appears in the conclusions themselves.
- **B3.** Given conclusions quoting `92.3%` where the report prints `92.3 to 98.0`, when the report is built, then it fails as unmatched.
- **B3.** Given a variant whose cost the report prints as `≥ $0.000781`, when the conclusions say it costs "$0.000781", then the build fails; when they say "at least $0.000781" or "≥ $0.000781", it succeeds.
- **B5.** Given the frozen dataset generated by `anthropic/claude-opus-5.5`, when any report is built, then it states the data is synthetic, names that model, and notes that the generator's vendor also makes variants under test.
- **B4.** Given conclusions containing `<script>`, when the report is built, then the page shows the text `<script>` and runs nothing.

## Success criteria

- The 2026-10-07 public report carries the owner's approved conclusions, and rebuilding it from saved results reproduces them byte for byte.
- No figure in any committed conclusions differs from the report it sits in.

## Assumptions

- The conclusions are prose in the owner's writing voice, drafted with the `/writing-voice` skill and approved before they are committed.
- A "figure" is a number with a unit or sign that the report itself prints: `94.0%`, `$0.000062`, `0.19 s`, `+1.0`, `-16.0`. Bare counts such as "200 messages" or "six variants" are not checked, since the report states them as context rather than as results.
- Both editions show the same conclusions. With nothing withheld today the two editions are almost identical anyway, and B3's check against the public edition keeps the conclusions publishable either way.
- The superseded first run gets no conclusions; only the current published run does.

## Risks and open questions

- **A matching figure can still be misused.** B3 proves a quoted number appears in the report, not that it is attached to the right variant or claim. "Jev reaches 94.0%" passes because 94.0% appears for Decisions. Catching that needs the owner's read, which is why approval before commit is part of the process rather than optional.
- **Rounding.** A conclusion that rounds ("about 1/30 the cost", "roughly 7x faster") quotes no figure and is unchecked. That is deliberate: ratios derived from report figures are analysis, not new measurements. Whether derived ratios should be checked too is open.
